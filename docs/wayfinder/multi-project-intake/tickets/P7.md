# Research how ols-qa-e2e runs on dev, reports failures and takes changes

## Question

ในเรโป `~/GitHub/ols-qa-e2e`: workflow ที่รันบน dev (`smoke-dev.yml`, `e2e-preprod.yml`) รันเมื่อไรและรันบนอะไร (runner, VPN, secret ที่ใช้ ชื่อเท่านั้น ห้ามคัดลอกค่า) · ผลไม่ผ่านไปอยู่ที่ไหน (artifact, report, round-json, Slack, Discord) และอ่านเป็นรายเคสได้อย่างไร · กติกาใน `CLAUDE.md` และ `docs/` เรื่องการแก้เทสต์ branch และ PR · สกิลที่เกี่ยวที่มีอยู่แล้ว (`playwright-best-practices`, `flaky-test-doctor`, `flaky-test-quarantine`, `code-review`) และสิ่งที่แต่ละตัวต้องใช้ · ห้ามแก้อะไรในเรโปนั้น

## Resolution

รายละเอียดอยู่ใน [P7-findings](../research/P7-findings.md)

- `smoke-dev.yml` ไม่เคยรันบน GitHub (0 run) ไม่มี cron และไม่มีอะไรส่ง event `dev-deploy` · รอบ dev จริงมาจาก launchd `com.thitichaya.ols-smoke-watch` ทุก 120 วินาที ผลอยู่ที่ `~/ols-qa-testing-bot/out/dev-smoke-*/run.json` และแจ้งเจ้าของทาง Discord DM
- อ่านเคสที่ไม่ผ่านรายเคสได้จาก `run.json` ด้วย jq (ใช้ error แรก ไม่ใช่รอบสุดท้าย) · MLV-008, MLV-030, FEED-124 ไม่ผ่านซ้ำสองรอบ
- กฎเรโป: ห้าม `test.skip`, `test.fixme` หรือเพิ่ม retry กลบ · ต้องยืนยัน env กับเจ้าของก่อนรันจริง · `failOnFlakyTests: true` · PR ไม่มี CI และไม่มี branch protection
- ทุก spec import `fixtures/test` ซึ่ง import `helpers` แก้สองไฟล์นี้ต้องรันชุดเต็ม
- `flaky-test-quarantine` ขัดกับกฎเรโปและกฎข้อ 7 ไม่ใช้เป็นขั้นอัตโนมัติ
- ความเสี่ยง: checkout ที่ smoke-watch ใช้ตามหลัง `origin/main` 68 commit และมีไฟล์แก้ค้าง 3 ไฟล์ การรันหลัง merge ต้องใช้ worktree แยก · รันซ้ำบน dev แบบไม่มีคนเฝ้าต้องได้คำยืนยัน env จากเจ้าของล่วงหน้า
