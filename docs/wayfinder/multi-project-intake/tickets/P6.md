# Grill the owner on the per-project config: source, intake rule, roles and skills

## Question

ไฟล์ตั้งค่าต่อโปรเจกต์ต้องมีอะไร (แหล่งงาน GitHub label หรือ Jira JQL, กฎรับงาน, ตำแหน่งที่ทำ, สกิลต่อชนิดงาน, ปลายทางเขียนผล, ช่องทางอนุมัติ) และ pluton-timesheet กับ OLS ใส่ลงรูปเดียวกันได้ไหม · เพดานงานพร้อมกันนับรวมหรือแยกโปรเจกต์

## Resolution

ปิดแล้ว: ไฟล์ตั้งค่าต่อโปรเจกต์มีหกช่อง และ Taskfolio กับ OLS ใส่ลงรูปเดียวกันได้

| ช่อง | Taskfolio | OLS | ที่มา |
|---|---|---|---|
| แหล่งงาน | GitHub label `agent:*` | Jira JQL ตาม QA Owner `customfield_12120` | P1, แผนแม่ข้อ 2 |
| กฎรับงาน | owner label และ Gate ตามแผนแม่ | "ทุกใบที่ ready to test และอยู่ชื่อเรา หรือ ใบไหนก็ตาม ที่ QA Owner เป็นเรา และสถานะยังไม่ done" · มีเทสเคสแล้วคือ TC Status DONE หรือ QA REVIEWED | MAP Notes, P3 |
| ตำแหน่งที่ทำ | PM, Dev, Tech Lead, QA, QA Lead ตามข้อ 2a | QA และ QA Lead | P3, ข้อ 2a |
| สกิลต่อชนิดงาน | ตารางข้อ 2a2 | สกิลในเรโป ols-qa เสมอ (`tc-fe-prep`, `tc-api-prep`, `tc-review`, `testing-ticket`, `review-result`, `retest-bug`) · ซ่อม e2e ใช้ `playwright-best-practices` และ `flaky-test-doctor` | ข้อ 2a2, P2, P8 |
| ปลายทางเขียนผล | PR และ issue บน GitHub | tab ใหม่ต่อ ticket ในชีท QA (`sheet_write.py --create-tab`) และคอมเมนต์ Jira หลังอนุมัติ | P9, P10 |
| ช่องทางอนุมัติ | DM แจ้งพร้อมลิงก์ `/approve` บน GitHub (ทางเลือก ก) | ตอบ `passed` ในเธรด DM (ทางเลือก ข) | แผนแม่ข้อ 8a |
