# Research what each OLS-QA skill needs and produces, and whether an agent can run it unattended

## Question

อ่านสกิลใน `~/GitHub/ols-qa/skills` (`tc-fe-prep-workflow`, `tc-api-prep-workflow`, `tc-review-workflow`, `testing-ticket-workflow`, `review-result-workflow`, `retest-bug-workflow`) แล้วตอบต่อสกิล: input ที่ต้องมี (Jira, Figma, Swagger, URL, บัญชีทดสอบ, VPN), ขั้นที่ต้องถามคนหรือรออนุมัติ, output และปลายทางที่เขียน (คอมเมนต์ Jira, CSV Qase, Google Sheet, Slack), และขั้นไหนรันโดยไม่มีคนเฝ้าไม่ได้ · ระบุจุดที่สกิลเขียนเทสเคสลงที่อื่นที่ไม่ใช่ "กูเกิลชีท qa" ตามที่เจ้าของสั่ง

## Resolution

รายละเอียดอยู่ใน [P2-findings](../research/P2-findings.md)

- **ไม่มีสกิลไหนเขียนเทสเคสลง Google Sheet ของ QA:** `tc-fe-prep` สร้าง CSV (`Draft_Jira`, `Import_Qase`) แล้วอัปโหลดและคอมเมนต์ใน Jira · ใน ols-qa มีแต่ placeholder ของ Sheet ID ค่าจริงอยู่ที่ `~/.ols-qa-secrets/` · การเขียนชีทผ่าน `sheet_write.py` นอกเรโปเท่านั้น และเป็นการเขียนผลเทส ไม่ใช่สร้างแถวเทสเคส
- **เกณฑ์ให้ AI เทสในคู่มือ OLS:** Status `READY TO TEST` และ TC Status `QA Reviewed` และต้องมีแถวเทสเคสในชีทแล้ว
- `testing-ticket` และ `retest-bug` มีจุดที่คนต้องแตะครั้งเดียวตอนจบรอบ และ retest มีโหมดที่เจ้าของมอบให้ทำได้เลย ยกเว้นเปิด bug ใหม่ · `tc-fe-prep` และ `tc-api-prep` หยุดรออนุมัติในแชทหลายจุด
- `tc-review` ต้องมีเอกสาร TC กับ ticket ที่มี AC/EC ไม่ได้ระบุว่าใครรัน · `review-result` ต้องมีชีทผลและคลิปบนดิสก์
- ช่องทางแจ้งผลในสกิลเป็น Discord ไม่ใช่ Slack · dev และ pre-prod ต้องต่อ VPN · retest ใช้ `sips` ของ macOS
- คำถามส่งต่อให้ P3 และ P4: เขียนเทสเคสลงแท็บไหนของชีท และยังโพสต์ Jira กับ CSV Qase ด้วยไหม · ใครรีวิวเทสเคสก่อนเป็น QA Reviewed · จุดรออนุมัติในสกิลแมปกับ DM Slack และคำตอบ `passed` อย่างไร · ให้ `tc-fe-prep` มีโหมดมอบอำนาจแบบ retest ไหม
