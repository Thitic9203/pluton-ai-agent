# Grill the owner on the e2e fix loop: trigger, triage rule, PR and the Slack DM

## Question

งานเริ่มจาก run แบบไหน (ทุก run ใน dev หรือเฉพาะรอบตั้งเวลา) · เคสที่ไม่ผ่านเพราะแอปพังจริงแจ้งใครและแจ้งอย่างไร (ไม่แก้เทสต์ให้ผ่าน) · PR ใช้ branch และหัวข้อแบบไหน (ตัดสินแล้ว: ตอบ `passed` ใน DM แล้ว QA Lead agent merge เอง) · DM Slack มีข้อมูลอะไร (เคส สาเหตุ diff หลักฐานรันผ่านกี่รอบ ลิงก์ PR) และตอบ `passed` แล้วเกิดอะไรต่อ · เพดานจำนวน PR ที่ agent เปิดค้างพร้อมกัน

## Resolution

คำตอบเจ้าของ (popup 14 Oct 2026):

- **env dev:** "อนุญาต dev ถาวร" agent รันซ้ำบน dev เองได้ เฉพาะ dev เท่านั้น pre-prod และ prod ยังต้องถามทุกครั้ง · รันจาก worktree แยกที่ตรงกับ `origin/main` ล่าสุด ไม่ใช้ checkout ที่ smoke-watch ใช้
- **ช่องทางแจ้ง:** "Slack DM ส่วน Discord คงเดิม" งานซ่อม e2e แจ้งทาง DM Slack ส่วน smoke-watch แจ้ง Discord เหมือนเดิม ไม่แก้
- **หลักฐานใน PR:** "รันชุดเต็มบน dev แนบผล" รันเคสที่แก้ซ้ำหลายรอบ และรันชุดเต็มเทียบกับผลก่อนแก้ แนบใน PR และใน DM
- **merge:** ตอบ `passed` ในเธรด DM แล้ว QA Lead agent merge เอง จากนั้นรันเคสนั้นและชุดเต็มบน dev อีกครั้ง (คำสั่งเจ้าของใน Notes ของแมพ)
