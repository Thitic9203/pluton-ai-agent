## Question

หน้า Agent Office ควรโฮสต์ที่ไหนให้เป็นส่วนตัวและฟรี และรับสถานะสดของ agent (label `agent:*` บน issue และ PR ของ branch `agent/issue-N`) ทางไหนโดยไม่มี token อยู่ในเบราว์เซอร์ และ roster ที่แก้ได้ (เพิ่มลดคน แก้หน้าที่หลัก) ควรเก็บที่ไหน เทียบอย่างน้อย Claude artifact (ความสามารถ db และการอ่านข้อมูลสด), JSON snapshot ที่ GitHub Actions เขียน, GitHub Pages ของเรโป private, Firebase Hosting site หรือ preview channel บนโปรเจกต์ Spark เดิม และ proxy แบบ Cloudflare Pages Function ที่เรโปใช้กับ Jira

## Resolution

หลัก: หน้า static บน Cloudflare Pages แยก staging และ prod พร้อม Pages Function อ่านอย่างเดียวที่ถือ credential ของ GitHub ฝั่ง server และตรวจ Firebase ID token แบบเดียวกับ Jira proxy (`functions/api/jira/_middleware.ts`) ฟรีที่ 100,000 request ต่อวัน ข้อมูลสดทุกครั้งที่โหลด ไม่ต้องเปิด Mac หรือ Claude ไว้ · ตั้งค่าโปรเจกต์อยู่ในไฟล์ `projects.config.json` ต่อโปรเจกต์ (source เป็น github หรือ jira) จึงเพิ่ม OLS ได้ด้วยการเพิ่มรายการ · roster แยกจาก config เก็บในที่ที่มีกฎสิทธิ์เขียน
สำรอง: Claude artifact (ส่วนตัว มี db สำหรับ roster) แต่ยังไม่มีทางที่มีเอกสารให้ Actions เขียนสถานะเข้าไป
ตัดออก: GitHub Pages เป็นสาธารณะแม้เรโป private (ต้องใช้ Enterprise Cloud ถึงจะ private) · Firebase site เพิ่มกินโควตาเดียวกับ staging จริง เกินแล้ว staging ถูกปิด
ต้องได้รับอนุมัติจากเจ้าของก่อนสร้าง: Cloudflare Pages project ใหม่ 2 ตัว และ credential ของ GitHub (กฎ global ข้อ 23)
